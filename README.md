# mcd-spec

点餐规格编译器。把预算、热量、忌口和优惠券编译成一份已经核过价的麦当劳购物车。

你说约束，它查门店菜单和营养表，把「不要酸黄瓜」「饮料换无糖」写进套餐的特调和子项，再用麦当劳的 `calculate-price` 算出应付金额。它停在核价，不会下单。

这是麦当劳程序员节创意开发大赛的参赛项目，由参赛者独立开发，不是麦当劳官方产品。餐品、价格和库存以麦当劳接口的实时结果为准。

## 目标用户

已经决定吃麦当劳，但还要同时满足预算、热量、忌口，并且想知道手里的券到底能省多少的人。

## 安装

需要 Python 3.11 或更高版本，没有第三方依赖。

```bash
git clone https://github.com/chius-me/mcd-spec.git
cd mcd-spec
```

实时查询需要麦当劳 MCP Token。在 [open.mcd.cn/mcp](https://open.mcd.cn/mcp) 用手机号登录后申请，只放到环境变量里：

```bash
export MCD_MCP_TOKEN="你的令牌"
python3 -m mcd_spec doctor
```

不要把令牌写进仓库、配置文件或命令行历史里打算提交的内容。`mcp-config.example.json` 里只有 `${MCD_MCP_TOKEN}` 占位符。

## 使用示例

离线示例不访问麦当劳，用来看编译器怎么做决定：

```bash
python3 -m mcd_spec compile --demo examples/spec.json
```

`examples/spec.json` 的规格是：预算 40 元，热量 700 kcal 以内，不要可乐和酸黄瓜，饮料偏好无糖，想吃鸡腿堡。示例输出：

上面为了阅读省掉了方案 2 和方案 3 的购物车 JSON。命令本身会把每份可核价购物车完整打出来。

这个结果说明编译器做了四件事：

- 板烧鸡腿堡去掉了酸黄瓜，并用券核价到 23 元，热量 540 kcal，成为满足规格的第一名。
- 薯条更便宜，但没有命中「想吃」。
- 麦辣鸡腿堡套餐已经换成无糖可乐并去掉酸黄瓜，子项热量仍是 771 kcal，所以不采用。
- 只剩可乐、没法换掉的套餐不会拿去核价。

连上真实门店时，把 `--demo` 换成城市和地点：

```bash
python3 -m mcd_spec compile \
  --city 上海 \
  --place 人民广场 \
  --budget 40 \
  --max-kcal 700 \
  --avoid 可乐,酸黄瓜 \
  --drink 无糖 \
  --want 鸡腿堡
```

也可以用文本规格：

```text
预算 40
热量 700
不要 可乐、酸黄瓜
饮料 无糖
想吃 鸡腿堡
城市 上海
地点 人民广场
```

场景用 `--scene` 指定：`pickup` 到店，`drive` 得来速，`delivery` 麦乐送。外送会读取账号里的地址；有多个地址时，命令会列出编号，再用 `--address-id` 指定。已经知道门店时，可以同时传 `--store-code` 和 `--be-code`。`--json` 输出结构化结果，`--no-coupon` 跳过优惠券。

## 边界

- 先按菜单标价排除明显超出预算的餐品。券后才进入预算的餐品，可能不会进入这一轮核对。
- 每次最多核对 6 个餐品的详情和核价，避免打满每分钟 600 次的接口限制。
- 热量来自 `list-nutrition-foods`。套餐按已选子项相加；酱料和配料的增减不改这个数字。
- 名称里包含忌口词就视为不合规格。如果这个名称同时包含饮料偏好，例如「不要可乐」且「饮料无糖」，会保留「无糖可口可乐」。
- 购物车 JSON 的金额字段沿用 `calculate-price` 的单位「分」。终端里的「核价」已经换成元。

调用了哪些工具、每一步为什么这么排，写在 [MCP_INTEGRATION.md](./MCP_INTEGRATION.md)。
